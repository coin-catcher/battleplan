# Skills Library — Implementation Tasks

Ordered tasks to add a **Skills Library** to BattlePlan: curated skills from public repositories, import/unimport into target repos, and **architecture stacks** selected when defining projects and code tasks.

---

## Task 1 — Define catalog data model and ship v1 curated files

**Goal:** A versioned catalog BattlePlan can load offline (bundled JSON) and refresh from git later.

**Steps:**

1. Adopt [catalog-schema.json](./catalog-schema.json) for validation in CI.
2. Generate `skills-catalog.v1.json` from [recommended-skills.yaml](./recommended-skills.yaml) and [architecture-stacks.yaml](./architecture-stacks.yaml) (build script in `scripts/` or `tools/`, not in `src/` until Task 2 consumes it).
3. Store taxonomy in [organization-taxonomy.yaml](./organization-taxonomy.yaml); categories drive UI tabs and filters.
4. Track upstream sources in [skill-repositories.csv](./skill-repositories.csv) with `trust_tier` and `update_strategy`.

**Acceptance criteria:**

- Catalog validates against schema; each skill has stable `id`, human `name`, `tier`, and resolvable `source`.
- Architecture stacks reference `default_skill_ids` that exist in the catalog or are explicitly marked `product_builtin`.

---

## Task 2 — Extend BattlePlan project/task persistence

**Goal:** Remember selected skills and architecture stack on projects and tasks (mindmap nodes).

**Steps:**

1. Extend `Project` and `ProjectTask` in `src/app/core/models.ts` (and `electron/document-types.ts`) with optional fields, for example:
   - `architecture_stack_id?: string`
   - `skill_bindings?: ProjectSkillBinding[]` (see schema)
   - `catalog_version?: number`
2. Mirror fields in IDB and file repository serializers; default empty arrays for backward compatibility.
3. Add migration-free defaults: missing fields behave as “no stack / no extra skills”.

**Acceptance criteria:**

- Saving and reloading a battleplan archive preserves stack and skill selections.
- Pending-changes and portability export include the new fields.

---

## Task 3 — Skills Library UI (browse, search, recommend)

**Goal:** Users quickly pick relevant skills without reading GitHub.

**Steps:**

1. Add a **Skills** panel (project level) and inline picker on **code task** create/edit:
   - Category sidebar from taxonomy (`featured` first).
   - Filters: Cloud Agent compatible, plugin bundle, requires MCP auth.
   - Badges: Featured, Recommended (pstack, cursor-team-kit), Suggested.
2. Show skill detail: description, source repo link, license, MCP auth warning, “included in stack X”.
3. **Recommend** skills when user selects an architecture stack (Task 5): pre-check `default_skill_ids`, allow user to deselect before import.
4. For research tasks, hide import actions (research must not vendor skills unless explicitly converted to code).

**Acceptance criteria:**

- User can add/remove skills from project or task selection without leaving BattlePlan.
- Selecting pstack surfaces poteto-mode and links to upstream README.

---

## Task 4 — Materialize skills into the target repository (import)

**Goal:** Cloud Agents see skills in-repo under `.cursor/skills/` (and optionally `.agents/skills/` for cross-tool repos).

**Why:** Cursor Cloud Agents do not receive the user’s `~/.cursor/skills/`; project skills in git are the portable mechanism ([Cursor skills docs](https://cursor.com/docs/skills)).

**Steps:**

1. Define **import strategies** per `source.type`:
   - `git_path` / `plugin`: shallow clone or GitHub raw/tree API; copy skill folder(s) to `.cursor/skills/<skill-name>/` preserving `SKILL.md` and bundled `scripts/`, `references/`, `assets/`.
   - `cursor_cloud_skill`: copy from BattlePlan-maintained template bundle in this repo.
   - `product_builtin`: no file copy; append DAR note only (desktop-only).
2. Record `repo_path`, `pinned_ref`, `import_state`, `imported_at` on each binding.
3. Trigger import via:
   - **(A) Automatic:** optional “Sync skills to repo” code task template executed before first code task on a project.
   - **(B) Manual:** button “Import selected skills” launches a code task whose Initial Prompt is generated by BattlePlan.
4. Generated Initial Prompt should instruct the agent to:
   - Branch from `starting_ref`, open PR against same ref.
   - Only add/update files under `.cursor/skills/` (and `.agents/skills/` if user enables vendor-neutral path).
   - Include a manifest file `battleplan/skills-lock.json` listing skill id, source URL, commit SHA, and paths (similar to lockfile).

**Acceptance criteria:**

- After import PR merges, a Cloud Agent run on a code task lists skills from the repo in environment (verify with a smoke task referencing a vendored skill description).
- MCP-only plugins show UI warning: skills may import but MCP still requires Cursor auth on desktop.

## Task 5 — Architecture stack selection at project and code-task creation

**Goal:** Opinionated stacks so users focus on features; agents use consistent technology.

**Steps:**

1. Load stacks from [architecture-stacks.yaml](./architecture-stacks.yaml) (or generated JSON).
2. **Project create / edit:** required dropdown “Architecture stack” with default `existing-codebase` when `repo_url` already contains app code (heuristic: `package.json`, `angular.json`, `wp-config.php`, `shopify.theme.toml`, etc.).
3. **Code task create:** inherit project stack; allow per-task override (e.g. parent project is Angular but one task is “Terraform only” → `cicd-github-terraform`).
4. On stack change, merge stack `dar` into project or task DAR under a fixed heading (same pattern as `formatDarSection` in `src/app/core/dar.ts`):
   - `### Architecture stack: <label>`
   - Body from YAML `dar` field.
5. When generating tasks from chat (`generateTasks`), include stack id and skill ids in the JSON schema prompt so proposed tasks align with stack.

**Acceptance criteria:**

- Executing a code task sends combined DAR: project rules + stack block + task rules + skill summary (Task 6).
- Stacks listed in research map 1:1 to user-requested options (WordPress, Shopify, Angular+S3, serverless, native, Electron, CI/CD).

## Task 6 — Inject skill instructions into agent launch (DAR integration)

**Goal:** Agents know which skills apply without relying on desktop `/` commands.

**Steps:**

1. In `launchWithFirstMessage` (`src/app/data/local-engine.ts`), after `collectTaskDarSections`, append:
   - `### Skills Library`
   - For each **imported** skill: name, repo path, one-line description, instruction “Follow the SKILL.md at `<path>` when relevant.”
   - For **selected but not yet imported** skills: warn agent to run import or ask user.
2. Optionally embed short excerpt (first ~500 tokens) of SKILL.md for critical BattlePlan skills only; full file remains in repo.
3. Respect inheritance: project skills + task skills − task-level `removed_skill_ids` (explicit removals).

**Acceptance criteria:**

- Agent prompt contains Skills Library section for code tasks; research tasks omit skill file expectations unless DAR mentions them.

---

## Task 7 — Unimport and cleanup

**Goal:** Users can remove skills from a project/task and from the git repo safely.

**Steps:**

1. UI: “Remove from project” vs “Remove from repository”:
   - **Selection only:** delete binding; no git change.
   - **Unimport:** generate code task to delete vendored paths and update `battleplan/skills-lock.json`.
2. Block unimport if another binding still references the same `repo_path` unless force flag.
3. Strip skill references from generated DAR when skill deselected.

**Acceptance criteria:**

- After unimport PR, lockfile and `.cursor/skills/<name>/` are gone; DAR no longer mentions skill.

---

## Task 8 — Catalog ingestion pipeline (maintainers)

**Goal:** Keep curated list fresh without manual YAML edits for every upstream change.

**Steps:**

1. Scheduled or manual job (GitHub Action in battleplan repo):
   - Pull `cursor/plugins` marketplace manifest; diff plugin list.
   - Parse `VoltAgent/awesome-agent-skills` README for new official entries (metadata only until reviewed).
   - Validate new SKILL.md files with agentskills spec (optional: SkillMD lint in CI).
2. Human review gate: new entries start as `experimental`; promote to `suggested` → `recommended` in PR review.
3. Pin `pinned_ref` on promote (commit SHA or release tag).

**Acceptance criteria:**

- Catalog PR shows diff of added/removed upstream skills; no automatic promotion to `recommended` without review.

---

## Task 9 — Security, licensing, and trust

**Goal:** Reduce supply-chain risk from arbitrary internet skills.

**Steps:**

1. Display license from SKILL.md frontmatter or repo LICENSE; block import if license missing and tier ≥ suggested (configurable).
2. Allowlist repositories by `trust_tier` from CSV; `experimental` may add custom git URL with user acknowledgment.
3. Scan vendored skills for obvious secrets patterns before merge (pre-commit or CI).
4. Document that third-party skills are **executable instructions**—same trust model as running an npm script.

**Acceptance criteria:**

- Custom URL import requires explicit checkbox; official repos import without extra friction.

## Task 10 — BattlePlan-first-party skills package

**Goal:** Dogfood the library in this repository.

**Steps:**

1. Add `.cursor/skills/battleplan/` with skills aligned to Cloud Agent workflows: walkthrough artifacts, env setup, subscribe-to-CI, code-task branch conventions.
2. Register them in catalog as `cursor_cloud_skill` or `git_path` pointing to this repo.
3. Default new BattlePlan projects (when repo is battleplan) to `existing-codebase` + `battleplan-walkthrough-artifacts` + `pstack-poteto-mode`.

**Acceptance criteria:**

- This repo’s own code tasks can use imported skills without manual copy.

---

## Task 11 — Generate Tasks and stack-aware planning

**Goal:** Planning agent proposes tasks that match stack and skills.

**Steps:**

1. Extend `GENERATE_TASKS_INSTRUCTION` payload in `local-engine.ts` with current `architecture_stack_id` and selected skill ids.
2. Add DAR snippet to project: “Prefer output_type code for implementation; research for spikes; subproject for large subtrees.”
3. Suggest a **bootstrap code task** “Import Skills Library selections” as first task when bindings exist but `import_state !== imported`.

**Acceptance criteria:**

- Generated task list includes bootstrap import task when needed; dependencies ordered before feature work.

---

## Task 12 — Documentation and UX copy

**Goal:** Users understand Cloud vs desktop skill behavior.

**Steps:**

1. README or in-app help: link to Cursor docs on project skills vs user skills.
2. Explain plugin marketplace (`/add-plugin pstack`) vs BattlePlan vendoring (for Cloud Agents).
3. Document recommended defaults: **pstack** for code quality, **cursor-team-kit** for CI, stack-specific bundles from [architecture-stacks.yaml](./architecture-stacks.yaml).

**Acceptance criteria:**

- New user can configure stack + skills and run first code task without external docs.
